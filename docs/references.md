# Official contract review

Reviewed during implementation and the final audit on 26 October 2026. These are source contracts, not evidence of a live integration test.

| Source                                                                                                                                                                                                                                                                                                      | Implementation consequence                                                                                                                                                                     |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [MCP 2026-07-28 tools](https://modelcontextprotocol.io/specification/2026-07-28/server/tools) and [specification repository](https://github.com/modelcontextprotocol/modelcontextprotocol)                                                                                                                  | Tool discovery/contracts, result shape, annotations and user authority. The compatibility transport advertises only its legacy revision.                                                       |
| [SDK v2 STDIO serving](https://ts.sdk.modelcontextprotocol.io/v2/serving/stdio.html), [resources](https://ts.sdk.modelcontextprotocol.io/v2/servers/resources.html), and [pinned package source](https://raw.githubusercontent.com/modelcontextprotocol/typescript-sdk/v2.4.0/packages/server/package.json) | Exact optional `@modelcontextprotocol/server@2.4.0`, `serveStdio` factory, tool/prompt/resource registration. Actual package installation remains unqualified locally.                         |
| [GitHub contribution guidelines](https://docs.github.com/en/communities/setting-up-your-project-for-healthy-contributions/setting-guidelines-for-repository-contributors)                                                                                                                                   | Read root, docs and .github guidance and applicable organization defaults.                                                                                                                     |
| [CODEOWNERS](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-code-owners)                                                                                                                                                         | Scoped owners, normal triage and draft behavior. Automatic routing provenance is not inferred from the mere presence of a file.                                                                |
| [Review request REST contract](https://docs.github.com/en/rest/pulls/review-requests)                                                                                                                                                                                                                       | Relevant targets, actor checks, explicit consent, permission failures and actual API confirmation. Requests can disappear after reviews are submitted. REST version is pinned to `2026-03-10`. |
| [REST rate limits](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api) and [GraphQL rate/query limits](https://docs.github.com/en/graphql/overview/rate-limits-and-query-limits-for-the-graphql-api)                                                                           | Bounded requests, rate-limit retry timing, read retries and resumable errors; no automatic retry of public writes.                                                                             |
| [PR standardization/templates](https://docs.github.com/en/pull-requests/reference/managing-and-standardizing-pull-requests)                                                                                                                                                                                 | Preserve template headings/order and include actual recorded verification. Host/human completes semantic checklist and legal obligations.                                                      |
| [Issue/PR search](https://docs.github.com/en/search-github/searching-on-github/searching-issues-and-pull-requests) and [GraphQL reference](https://docs.github.com/en/graphql)                                                                                                                              | Search is coarse discovery; direct issue refresh, timeline scans and secondary PR checks determine eligibility.                                                                                |
| [GraphQL project types](https://docs.github.com/en/graphql/reference/projects) and [project API examples](https://docs.github.com/en/issues/planning-and-tracking-with-projects/automating-your-project/using-the-api-to-manage-projects)                                                                   | Visible board user/status/text fields participate in reservation checks; partial/unfamiliar fields remain unresolved.                                                                          |
| [GitLab issues](https://docs.gitlab.com/api/issues/), [merge requests](https://docs.gitlab.com/api/merge_requests/), and [Forgejo API usage](https://forgejo.org/docs/latest/user/api/usage/)                                                                                                               | Instance-specific forge adapters and conservative capability reporting. Live permission/feature matrices remain outstanding.                                                                   |

Client configuration, API permissions, token capabilities and instance extensions can change. The pinned bridge and contract fixtures reduce drift; the external qualification checklist in the release report must still run with the actual hosts and accounts before broad release.
